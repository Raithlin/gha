# v0.4.0-beta.1

This first beta adds PR worktrees, supports more coding agents, and adds
Homebrew and native Linux packages. If you find a problem, include the output
of `gha version --format json` in your report.

## Before you upgrade

Commands that change local or GitHub state now **execute by default** after
their safety checks. Use `--dry-run` to preview changes. We removed the old
confirmation flag. Check scripts that rely on commands running as previews.
Explicit targets and safety checks still apply.
[#16](https://github.com/Raithlin/gha/pull/16).

Upgrade the executable through its package manager or release archive first.
Then run `gha update --dry-run` to preview agent guidance changes and
`gha update` to apply compatible changes. This command updates guidance only.

## Install or upgrade

On macOS, run `brew install --cask raithlin/tap/gha`. To upgrade, run
`brew update`, then `brew upgrade --cask gha`. The release workflow updates
the [Homebrew tap](https://github.com/Raithlin/homebrew-tap) automatically.

Linux users can download Debian/Ubuntu, Fedora, or Arch packages. Linux and
macOS archives remain available for amd64 and arm64. Verify downloads against
this release's `checksums.txt`. To upgrade a Linux package, download the new
version and install it with your package manager. GHA does not host apt, dnf,
or pacman repositories.

After you install, run `gha version --format json`. Its `version` field should
read `0.4.0-beta.1`. Run `gha agent install` to set up agent guidance separately.

See the [setup guide](https://github.com/Raithlin/gha/blob/v0.4.0-beta.1/docs/getting-started.md)
and [distribution guide](https://github.com/Raithlin/gha/blob/v0.4.0-beta.1/docs/package-distribution.md)
for instructions. The macOS binaries are not signed with an Apple Developer ID
or notarized. [#31](https://github.com/Raithlin/gha/pull/31),
[#32](https://github.com/Raithlin/gha/pull/32).

## Changes

- **Work on PRs in separate checkouts.** Use `gha pr checkout <number> --worktree <path>`
  to check out or resume a PR. GHA reports where to push changes, including
  PRs from forks. `gha pr retire` removes eligible checkouts for closed or
  merged PRs. It preserves local edits, unpublished commits, locked checkouts,
  and work whose safety it cannot establish. You can also list, add, and remove
  worktrees directly. [#23](https://github.com/Raithlin/gha/pull/23),
  [#26](https://github.com/Raithlin/gha/pull/26).
- **See which branch changes completed.** Branch commands check where Git will
  push and whether another Git operation is in progress. If a command partly
  fails, its JSON output records the changes that completed. On origin, a
  rename updates both branch names together or leaves both unchanged.
  [#21](https://github.com/Raithlin/gha/pull/21),
  [#24](https://github.com/Raithlin/gha/pull/24),
  [#25](https://github.com/Raithlin/gha/pull/25).
- **Set up more coding agents.** GHA supports Codex, Claude Code, Pi, OpenCode,
  GitHub Copilot, Gemini CLI, Cursor, Hermes Agent, and OpenClaw. The installer
  detects agents you have set up without requiring their executables. Use
  `--agent` to select them explicitly. Shorter default guidance keeps the
  detailed skill available when needed.
  [#14](https://github.com/Raithlin/gha/pull/14),
  [#19](https://github.com/Raithlin/gha/pull/19),
  [#20](https://github.com/Raithlin/gha/pull/20),
  [#22](https://github.com/Raithlin/gha/pull/22).
- **Keep guidance compatible with your binary.** `gha update` checks that your
  binary supports the commands a skill requires. It preserves skills you
  customized and rejects updates your binary cannot support.
  [#18](https://github.com/Raithlin/gha/pull/18),
  [#19](https://github.com/Raithlin/gha/pull/19).
- **Reuse your GitHub login and draft PR descriptions.** GHA can reuse your `gh`
  login when `GHA_GITHUB_TOKEN` is unset. `gha pr prepare` drafts a description
  from local commits without fetching or creating a PR.
  [#15](https://github.com/Raithlin/gha/pull/15),
  [#17](https://github.com/Raithlin/gha/pull/17).
- **Check release readiness with better diagnostics.** Release checks use CI
  results for the selected commit and account for workflow retries. They accept
  skipped or neutral jobs alongside successful validation. GHA also reports
  build details and explains problems with unpublished branches or deleted
  upstream branches. Release publication checks the target and requires reviewed
  notes when the workflow requests them.
  [#12](https://github.com/Raithlin/gha/pull/12),
  [#13](https://github.com/Raithlin/gha/pull/13),
  [#26](https://github.com/Raithlin/gha/pull/26),
  [#28](https://github.com/Raithlin/gha/pull/28).

Install and upgrade tests cover Debian, Fedora, Arch, Intel Mac, and Apple
Silicon. They check that package operations preserve customized guidance and
that Homebrew rejects a download with the wrong checksum.

Commands to wait for a release or verify downloaded assets remain planned.
To verify a release, check its GitHub Actions run, published release, and
downloads. Use `gha capabilities --format json` to list available commands.
